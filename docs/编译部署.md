# 编译与部署

这份代码基于上游稳定 tag `v1.7.0`（2026-10-27），另加一处改动：OpenAPI 成功响应里的 `application/json` schema 会写进 MCP `tools/list` 的 `outputSchema`。

不要编译 `main`。fork 的 `main` 跟的是上游开发主线，比 `v1.7.0` 超前，不是这次要上线的版本。仓库里没有名叫 stable 的分支，稳定版就是 tag。

要编译的 tag 是 `v1.7.0-openapi-output-schema`。

## 取出代码

```bash
git clone git@github.com:sword0307/agentgateway.git
cd agentgateway
git fetch --tags origin
git checkout v1.7.0-openapi-output-schema
```

检出后工作区必须是干净的。`git status` 没有改动再编译，否则二进制里的版本号会带 `-dirty`。

## 编译

只要网关进程，不要管理界面时用下面这组。这是建议的编译方式。

依赖：

- `git`、`make`、`curl`
- Rust `1.99.0`。仓库根目录的 `rust-toolchain.toml` 写死了这个版本，装过 rustup 后，下面的 `cargo` / `make` 会自己安装，不要改用系统里别的 Rust
- 能访问 `crates.io`、`github.com`、`gitlab.com`

`Cargo.toml` 里有几份没有发到 crates.io 的 git 依赖，编译机必须能拉到这些固定提交：

- `https://github.com/howardjohn/schemars`
- `https://gitlab.com/howardjohn/http-serde`，提交 `c2e482be0ddf029895ba72ef8749b9f94b388fc7`
- `https://github.com/howardjohn/wiremock-rs`
- `https://github.com/howardjohn/async-openai`
- `https://github.com/howardjohn/yaml-serde-edit`
- `https://github.com/howardjohn/rust-tiktoken`

在仓库根目录执行：

```bash
export CARGO_NET_GIT_FETCH_WITH_CLI=true
export VERSION=v1.7.0-openapi-output-schema
make build UI=0
```

`UI=0` 不跑 Node，也不把管理界面打进二进制。产物是：

```text
target/release/agentgateway
```

核对版本：

```bash
./target/release/agentgateway --version
```

`version` 应是 `v1.7.0-openapi-output-schema`。没设置 `VERSION` 时，这里显示的是 git 提交号。

GitHub 走 HTTPS 超时、SSH 可以通时，保留上面的 `CARGO_NET_GIT_FETCH_WITH_CLI=true`，再让 git 把 GitHub HTTPS 转成 SSH：

```bash
git config --global url."git@github.com:".insteadOf "https://github.com/"
```

`gitlab.com` 这条依赖没有对应的 SSH 替代。GitLab 连不上时，`http-serde` 拉不下来，编译会在取依赖阶段失败。

### 带管理界面

需要页面时再装 Node `24.22.1`（`ui/.nvmrc`）。pnpm `11.20.0` 由 Node 自带的 corepack 安装，不用单独装 pnpm。

```bash
export CARGO_NET_GIT_FETCH_WITH_CLI=true
export VERSION=v1.7.0-openapi-output-schema
make build
```

产物路径相同。界面嵌在二进制里，默认地址是 `http://localhost:15000/ui`。`outputSchema` 只出现在 MCP JSON-RPC 里，这个页面不展示它。

## 直接把产物交给运维

可以。运维机器上不需要 Rust、Node，也不需要访问 GitHub 或 GitLab。交给运维的是编好的 `agentgateway` 可执行文件。业务配置继续用线上现有的那份，OpenAPI 文件路径、上游地址和端口都在配置里，不在二进制里。

二进制必须在目标系统上编译。在 macOS arm64 上执行 `make build` 得到的文件只能在同样的 Mac 上跑，不能放到 Linux 服务器上。线上如果是 Linux x86_64，就在 Linux x86_64 上执行上面的 `make build UI=0`，把 `target/release/agentgateway` 拷给运维。用容器部署时，交对应架构的镜像，入口仍是 `/app/agentgateway`。

运维替换二进制后，启动命令不变：

```bash
./agentgateway --version
./agentgateway -f /path/to/现有配置.yaml
```

`version` 应是 `v1.7.0-openapi-output-schema`。配置不用为 `outputSchema` 改格式。`tools/list` 会多出这个字段。

## 部署

自己编译时，把 `target/release/agentgateway` 和一份配置文件拷到机器上。配置格式用仓库里的 `examples/mcp-openapi/config.yaml` 做参照，OpenAPI 目标写成实际的 schema 文件和上游 host。

```bash
./agentgateway -f /path/to/config.yaml
```

`-f` 就是 `--file`。进程按配置文件里的端口监听。改配置文件后，进程会重新加载这份文件。

容器构建用同一份代码：

```bash
export CARGO_NET_GIT_FETCH_WITH_CLI=true
make docker
```

镜像名是 `ghcr.io/agentgateway/agentgateway:` 加上 `git describe` 的结果。Docker 构建会编进管理界面，并且构建过程同样要能访问 GitHub 和 GitLab。入口是 `/app/agentgateway`，运行时同样加 `-f` 指向配置文件。
