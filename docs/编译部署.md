# 编译与部署

这份代码基于上游稳定 tag `v1.7.0`（2026-10-27）。OpenAPI 成功响应里的 `application/json` schema 会写进 MCP `tools/list` 的 `outputSchema`。`outputSchema` 从协议 `2025-06-18` 起就在工具定义里，`2025-11-25` 仍然保留。Cursor 目前能完成 `initialize` 的最高版本是 `2025-11-25`。OpenAPI 的 `initialize` 应答使用客户端请求里的握手版本；客户端带来 `2025-11-25` 时，应答也是 `2025-11-25`。

不要编译 `main`。fork 的 `main` 跟的是上游开发主线，比 `v1.7.0` 超前，不是这次要上线的版本。仓库里没有名叫 stable 的分支，稳定版就是 tag。

要编译的分支是 `release/v1.7.0-2025-11-25-output-schema`。

## 取出代码

```bash
git clone git@github.com:sword0307/agentgateway.git
cd agentgateway
git fetch origin
git checkout release/v1.7.0-2025-11-25-output-schema
```

检出后工作区必须是干净的。`git status` 没有改动再编译，否则二进制里的版本号会带 `-dirty`。

## 编译

管理端要打开 `/ui` 时，用带界面的编法。`ui/dist` 没打进二进制时，`/ui` 会 404；`/` 仍返回内置纯文本页 “Agentgateway Admin”，不会跳到 `/ui`。只跑 MCP、不提供这个页面时，才用后面的 `UI=0`。

依赖：

- `git`、`make`、`curl`
- Rust `1.99.0`。仓库根目录的 `rust-toolchain.toml` 写死了这个版本，装过 rustup 后，下面的 `cargo` / `make` 会自己安装，不要改用系统里别的 Rust
- 能访问 `crates.io`、`github.com`、`gitlab.com`

`Cargo.toml` 里有几份没有发到 crates.io 的 git 依赖，编译机必须能拉到这些固定提交：

- `https://github.com/howardjohn/schemars`
- `https://gitlab.com/howardjohn/http-serde`，提交 `c2e482be0ddf029895ba72ef8749b9f94b388fc7`
- `https://github.com/howardjohn/wiremock-rs`
- `https://github.com/howardjohn/async-openai`
- `https://github.com/howardjohn/yaml-serde-edit`
- `https://github.com/howardjohn/rust-tiktoken`

`http-serde` 是公网 GitLab 上的公开仓库，不是私有仓库，也不在 GitHub 上。连不上 `gitlab.com` 时，`cargo build` 在取依赖阶段失败，不会开始编本仓库的代码。不要把 `http-serde` 改成某台机器上的本地 `path`，否则别人拉下来编不过。

GitHub 走 HTTPS 超时、SSH 可以通时，保留 `CARGO_NET_GIT_FETCH_WITH_CLI=true`，再让 git 把 GitHub HTTPS 转成 SSH：

```bash
git config --global url."git@github.com:".insteadOf "https://github.com/"
```

带界面时还要 Node `24.22.1`（`ui/.nvmrc`）。pnpm `11.20.0` 由 Node 自带的 corepack 安装，不用单独装 pnpm。

在仓库根目录执行：

```bash
export CARGO_NET_GIT_FETCH_WITH_CLI=true
export VERSION=v1.7.0-2025-11-25-output-schema
make build
```

`make build` 会先在 `ui/` 执行 `corepack pnpm install --frozen-lockfile` 和 `corepack pnpm build`，再执行 `cargo build --release --features ui`。`ui/dist` 打进二进制。产物是：

```text
target/release/agentgateway
```

核对版本：

```bash
./target/release/agentgateway --version
```

`version` 应是 `v1.7.0-2025-11-25-output-schema`。没设置 `VERSION` 时，这里显示的是 git 提交号。

本机启动后做这几项检查。管理端口默认是 `127.0.0.1:15000`。

```bash
curl -sI http://127.0.0.1:15000/ | head -n 1
curl -sI http://127.0.0.1:15000/ui | head -n 1
curl -s http://127.0.0.1:15000/ui | head -n 20
```

带界面的二进制上，`/` 是 `308`，`Location` 指向 `/ui`；`/ui` 是 `200`，HTML 标题是 `agentgateway`，并引用 `/ui/assets/` 下的脚本和样式。页面能渲染出侧边栏，版本号是 `v1.7.0-2025-11-25-output-schema`。`outputSchema` 只出现在 MCP `tools/list` 里，这个页面不展示它。

对外的管理域名要转到这个管理端口。转到 MCP 业务端口时，路径对了也会 404。

### 不要管理界面

只要网关进程、不提供 `/ui` 时：

```bash
export CARGO_NET_GIT_FETCH_WITH_CLI=true
export VERSION=v1.7.0-2025-11-25-output-schema
make build UI=0
```

`UI=0` 不跑 Node。这种二进制访问 `/ui` 就是 404。

## 直接把产物交给运维

可以。运维机器上不需要 Rust、Node，也不需要访问 GitHub 或 GitLab。交给运维的是编好的 `agentgateway` 可执行文件。业务配置继续用线上现有的那份，OpenAPI 文件路径、上游地址和端口都在配置里，不在二进制里。

二进制必须在目标系统上编译。在 macOS arm64 上编出来的文件只能在同样的 Mac 上跑。线上如果是 Linux x86_64，就在 Linux x86_64 上执行上面的 `make build`，把 `target/release/agentgateway` 拷给运维。管理端这份必须是带界面的产物；用 `UI=0` 的产物替换后，`/ui` 仍是 404。用容器部署时，交对应架构的镜像，入口仍是 `/app/agentgateway`。`make docker` 会编进管理界面。

运维替换二进制后，启动命令不变：

```bash
./agentgateway --version
./agentgateway -f /path/to/现有配置.yaml
```

`version` 应是 `v1.7.0-2025-11-25-output-schema`。配置不用为 `outputSchema` 改格式。`tools/list` 会多出这个字段。

## 部署

自己编译时，把 `target/release/agentgateway` 和一份配置文件拷到机器上。配置格式用仓库里的 `examples/mcp-openapi/config.yaml` 做参照，OpenAPI 目标写成实际的 schema 文件和上游 host。

```bash
./agentgateway -f /path/to/config.yaml
```

`-f` 就是 `--file`。进程按配置文件里的端口监听。

热更新只盯 `-f` 这一份文件。文件内容改了会重新加载；同目录里新增的另一个配置文件不会被读。顶层 `config`（DNS、admin、session key）只在启动时生效。MCP target 写进这份文件后会进内存，但已经 `initialize` 的会话仍用当时的 target 列表，客户端要重新建立会话才能在 `tools/list` 里看到新 target。

容器构建用同一份代码：

```bash
export CARGO_NET_GIT_FETCH_WITH_CLI=true
make docker
```

镜像名是 `ghcr.io/agentgateway/agentgateway:` 加上 `git describe` 的结果。Docker 构建会编进管理界面，并且构建过程同样要能访问 GitHub 和 GitLab。入口是 `/app/agentgateway`，运行时同样加 `-f` 指向配置文件。
